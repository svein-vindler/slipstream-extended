# Diagnosing a refresh that cannot find a new workout

A failed job, an old dispatch reservation and incomplete stored data are
different conditions. Check the exact operation/run before starting another
job; a terminal workflow does not prove that the requested activity was fetched.

A targeted, explicitly authorized activity sync reads stored data first.
When summary candidates do not cover the requested local date, it can inspect
one bounded canonical discovery page per relevant year. If that page is
truncated, the result is `activity_discovery_incomplete`, with
`bounded_activity_discovery` in missing components. It does not claim an empty
day, select a workout from partial results, increase the listing limit or
paginate through history. The explicit sync can still proceed through the
existing duplicate guard, cooldown and source-request budgets.

R2 denials, unknown read outcomes and truncated exact-activity artifact/context
enumerations still stop their affected operation. A stored activity ID can be
supplied to avoid broad discovery when the installer already knows it.

See the maintainer workflow for privacy-safe source failure categories and the
manual connection check. An authenticated connection check does not verify
that the workout exists or that its Coach Input is ready.
